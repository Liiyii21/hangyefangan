合规红线

六条不可逾越的边界

①
不出具诊断证明　AI 输出仅限症状预判与就诊优先级建议,严禁生成任何具有法律效力的诊断报告或病历(《动物诊疗机构管理办法》第 14 条,执业兽医方可出具)
②
不开具处方　平台禁止推荐具体处方药品名称、剂量及用药方案,兽药处方须由注册执业兽医师在问诊后单独出具(《兽药管理条例》第 38 条)
③
不代售处方兽药　平台不销售处方类兽药及疫苗,不收取药品销售佣金,OTC 兽药导购须注明「请遵医嘱」(《兽药经营质量管理规范》)
④
宠物医疗数据最小化采集　宠物影像、血检报告等数据仅用于当次 AI 分析,不用于模型训练须单独授权,用户可随时申请删除(《个人信息保护法》第 6、47 条)
⑤
未成年用户保护　14 岁以下未成年人注册须经监护人实名同意,平台不向未成年人推送付费升级弹窗(《未成年人网络保护条例》第 17 条)
⑥
执业资质可查　所有参与在线复核的兽医师须上传执业兽医师资格证并经平台审核,证件编号在咨询界面一键可验(《执业兽医管理办法》第 8 条)

02ARCHITECTURE

产品主线 · 五屏信息架构与视觉语言

PawMind 的产品主线遵循「焦虑降级 → 认知建立 → 行动闭环」三段式设计哲学。宠主在最脆弱的深夜打开 App 时,第一屏必须在 3 秒内给出安全感而非表单;第五屏必须让执业兽医的专业背书触手可及。每一屏的信息密度与交互成本需严格匹配宠主当下的情绪状态。

五屏产品主线

1 · 分诊入口　宠主进入后首先选择宠物档案(已有档案一键调取,新宠 30 秒建档),随即进入症状快速描述流:自然语言输入 + 部位图点选 + 拍照上传三路并行,AI 在 8 秒内返回「紧急程度评级 + 初步方向 + 就诊建议」,卡片化呈现,字号不低于 16px

03AI CORE

AI 核心模块设计 · 三层编排架构

PawMind 的 AI 不是一个单一模型,而是三层职责清晰的编排体系:症状问诊树洞负责「听懂焦虑」,病历结构化引擎负责「沉淀记忆」,行业安全围栏负责「守住底线」。三层之间通过统一的 Context Window 传递状态,任何一层触发拦截都可中断整条链路并强制转人工。设计原则是:AI 永远是辅助,兽医才是最终判断者。

模块一 · 症状问诊树洞(Claude Sonnet 驱动)

核心作用 / Prompt 摘要 / 失败兜底 / 合规边界

①
核心作用　接收宠主以自然语言、语音转文字或图片描述的症状,经过多轮追问(最多 8 轮)收集完整病史,输出「紧急程度五级评级(P1-P5)+ 可能方向 + 建议下一步行动」三段式卡片,响应 P95 延迟目标 ≤ 4 秒,支持中英双语混合输入
②
Prompt 摘要　System Prompt 核心约束共 11 条:角色设定为「有执照的兽医助手」而非「执业兽医」;必须追问年龄、体重、绝育状态、既往病史、当前用药 5 项基本病史;禁止输出确诊结论,只输出「可能涉及的方向」;每轮回复末尾强制追加免责声明模板(不少于 40 字);涉及处方药名称时只允许提及药物类别,不得给出具体剂量;Temperature 设置为 0.3 以保证医疗语境下的稳定性
③
失败兜底　Claude API 超时(阈值 6 秒)或返回 5xx 时,自动降级至规则引擎:基于 120 条预设症状决策树给出简化评级,同时前端展示「AI 响应延迟,已为您提供基础建议,建议咨询在线兽医」提示条,不允许静默失败;降级模式下所有回复标注「规则引擎输出」水印,区别于 AI 生成内容
④
合规边界　依据《执业兽医管理办法》第 8 条与《动物诊疗机构管理办法》第 3 条,平台 AI 不得做出「诊断」行为,仅提供信息参考。所有输出经合规过滤器二次扫描,检测「确诊为」「一定是」「肯定不是」「打这个针就好了」等确定性违规词,命中即拦截并替换为合规措辞

模块二 · 病历结构化引擎(GPT-4o + BGE-M3 双模型)

核心作用 / Prompt 摘要 / 失败兜底 / 合规边界

①
核心作用　在每次问诊会话结束后 30 秒内,自动将对话全文结构化为标准病历摘要:宠物基本信息 + 主诉关键词(≤ 5 个)+ 症状时间线 + AI 建议摘要 + 兽医复核结论(若已完成人工环节);摘要存入 PostgreSQL 并生成 BGE-M3 向量嵌入,用于后续同类症状检索与兽医匹配权重计算,向量维度 1024
②
Prompt 摘要　GPT-4o 摘要 Prompt 采用 JSON Schema 强制输出格式,包含 12 个字段:pet_id / session_id / chief_complaint / symptom_list / duration_days / severity_level(P1-P5)/ ai_suggestions / vet_review_required(bool)/ disclaimer_appended(bool)/ language / token_count / created_at;Temperature 设为 0,确保结构化输出零随机性;摘要生成失败重试 3 次,超出则写入降级纯文本字段
③
失败兜底　GPT-4o API 不可用时切换至 Claude Sonnet 执行同一 JSON Schema 摘要任务(双模型热备);若两路均失败,原始对话文本以加密形式写入 OSS 冷存储,异步任务队列标记为「待结构化」,72 小时内 cron 任务自动重试,期间用户档案页显示「病历整理中」状态而非空白
④
合规边界　病历数据属于《个人信息保护法》第 28 条定义的敏感个人信息,存储前经 libsodium XChaCha20-Poly1305 客户端加密,密钥由用户 PIN 派生,平台服务端不持有明文;数据留存周期默认 5 年(与双录一致),用户可主动申请删除并在 15 个工作日内完成全链路清除

模块三 · 行业安全围栏(危机识别 · 强制导流 · 不替代专业判断)

危机词识别 / 强制导流 / 转人工机制 / 不替代专业判断原则

①
危机词实时识别　每一条用户输入与 AI 输出均经过双层扫描:第一层为关键词正则匹配,覆盖「吐血」「抽搐超过 3 分钟」「呼吸停止」「意识丧失」「骨折外露」「中毒」等 64 个 P1 级危机词及其同义变体;第二层为语义向量相似度检测(阈值 cosine ≥ 0.88),识别表述迂回但语义命中危机的输入,两层任一触发即进入强制导流流程,延迟目标 ≤ 200ms
②
强制导流流程　危机词触发后 AI 立即停止当前生成(stream abort),前端全屏弹出红色警示卡片:顶部「紧急情况 · 请立即行动」标题 + 就近急诊宠物医院地图(调用高德 API 取半径 5km 内 24 小时急诊)+ 平台紧急兽医热线(响应 SLA ≤ 90 秒)+ 「我已了解,继续 AI 问诊」二次确认按钮(字号降至 12px 且需等待 5 秒方可点击);此卡片不可被侧滑关闭,只能通过显式确认或拨打热线消除
③
转人工机制　以下 4 种情形强制转人工且不可由 AI 自行解除:连续 3 轮用户对 AI 建议表达不满或困惑(情绪识别模型检测)/ 评级上升至 P1 或 P2 / 涉及处方药剂量追问超过 2 次 / 宠主明确输入「我不相信 AI 我要真人」;转人工后系统自动匹配空闲兽医并在 90 秒内建立视频通道,排队超时则升级为电话回拨;整个转接过程的上下文摘要自动推送给接入兽医,不需宠主重复描述
④
不替代专业判断原则　安全围栏的核心设计哲学写入产品宪法第 1 条:AI 的职责是「降低信息不对称、辅助宠主做出就诊决策」,而非「替代执业兽医做出临床判断」。为此,所有 AI 输出经独立合规过滤器(基于规则 + 微调分类模型,准确率目标 ≥ 99.2%)二次审核;过滤器每季度由外部兽医委员会(不少于 3 名执业兽医)审查一次词库与阈值,审查记录留存备查;平台年度合规报告向监管部门主动披露 AI 拦截率、转人工率与误判率三项核心指标
为什么这套 AI 编排值得信赖　PawMind 的三层架构从设计上就拒绝了「让 AI 尽可能多地回答问题」的商业诱惑。模块一的 Temperature 0.3 与 11 条硬约束,确保树洞永远谦逊;模块二的双模型热备与 72 小时重试队列,确保记忆不丢失;模块三的 64 词危机库 + 200ms 拦截 + 90 秒转人工 SLA,确保底线不被突破。三层加在一起的答案是:这套 AI 不是在模拟兽医,而是在帮宠主更快、更准地找到真正的兽医。
